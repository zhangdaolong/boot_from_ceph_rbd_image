## Firmware implementation status

The current UEFI package has host-tested protocol code, a validated firmware configuration source, a Driver Binding protocol that maps the configured image, a read-only Block I/O publication path, and a CephX MAuth handshake driven from the messenger connect flow. A bounds-checked CRUSH decoder (`CephRbdCrush.c`) and OSDMap placement decoder (`CephRbdPlacement.c`) map object names to PGs and acting OSD sets; both are verified against vectors captured from a real cluster. A host-side live probe has validated connect + CephX authentication + `MON_GET_MAP` + `osd getmap` + object-to-OSD placement against a real Ceph 22 monitor (18-byte paxos header, `__s16` session_mon field). It is still **not a working Ceph boot driver**: no EDK II/OVMF build has been run, the final AUTH ticket session key is not parsed, OSD ops are still sent over the monitor connection rather than to the primary OSD, and GPT/ESP discovery is missing.
